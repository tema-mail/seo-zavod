Коротко

Что строим. Приложение для Мака и Windows. Человек его скачивает, проходит мастер настройки и получает SEO-завод: сбор спроса, карта страниц, тексты, проверка, выкладка на сайт, замер позиций. Работает на подписке Codex или Claude, ключи API – запас. Прогноз – ~310–420 часов до продажи.

Важное ограничение (проверено в документации Anthropic 14.11.2026). Для студии подписка Claude законна: долгий токен официально сделан «для CI и скриптов», но у каждого человека своя подписка. В продаваемой версии Anthropic запрещает сторонним продуктам предлагать вход по подписке claude.ai без их одобрения. Поэтому у клиента Claude подключается ключом API или после одобрения Anthropic; Codex по подписке ChatGPT – допускается, но OpenAI для автоматизации советует ключ API. Подробно – в разделе «Условия Anthropic и OpenAI».

Где что работает. Нейросети и движок завода стоят на сервере в Нидерландах и работают круглые сутки. Компьютер нужен, чтобы смотреть, утверждать и давать задания. Выключил ноутбук – завод работает дальше.

Для кого. Сначала для студии: ты и команда, наши сайты. Потом продаём, как Васин свой Цех. Поэтому с первого дня в коде ничего не зашито под нас: ни сервера, ни ключей, ни путей.

Не входит: сайты и вёрстка, тексты Дзен/ВК, Ева, Штаб, остальные агенты студии. Текущий код (прототип seozavod, avtostati, админка TEYES, РУКИ, бот Евы) не трогаем – решаем по нему, когда завод встанет.

Чем мы сильнее: настоящее приложение вместо терминала, завод не зависит от включённого компьютера, Claude из России работает через сервер NL, коммерческие страницы, а не только блог.

Путь человека: от скачивания до работы

  1. Скачал и открыл. Файл .dmg для Мака или .exe для Windows.
  2. Сервер. «У вас есть сервер?» Есть – адрес, порт, логин, пароль один раз. Нет – инструкция, какой взять (Нидерланды, Ubuntu 24; минимум 2 ядра и 4 ГБ – один писатель за раз; рекомендуем 4 ядра и 8 ГБ – допущение, уточняем замером на пилоте). Приложение само делает SSH-ключ и кладёт его на сервер. Вход по паролю отключается только после того, как отдельное соединение по ключу прошло, – иначе клиент потеряет доступ к своему серверу.
  3. Установка движка. Одна кнопка. Приложение по SSH ставит Python, Node, Claude Code, Codex, движок, службу автозапуска. Видно прогресс по шагам; в конце – «Доктор» проверяет всё сам.
  4. Нейросети.
    • Claude, режим студии: приложение запускает на сервере claude setup-token, показывает ссылку, человек входит в браузере, вставляет код. Токен живёт на сервере год. Этот путь уже работает у бота Евы.
    • Claude, продаваемая версия: ключ API из Claude Console (оплата по расходу) – пока Anthropic не одобрит вход по подписке (вопрос 9).
    • Codex по подписке: вход по коду устройства codex login --device-auth (флаг есть в коде Codex, в документации – бета, включается в настройках безопасности ChatGPT). Если вход по коду не включён – ключ API OpenAI. Входить в Codex на компьютере клиента не требуем: на компьютере нет ни терминала, ни ключей.
    • Ключи API: поле на каждый сервис и кнопка «Проверить» – живой запрос, показываем код ответа.
    • Роли: кто стратег, кто автор, кто редактор – готовые настройки, можно поменять.
  5. Данные. XMLRiver (ключ + потолок денег), Яндекс Вебмастер и Метрика (вход через Яндекс), Search Console (файл ключа), Telegram для уведомлений – по желанию.
  6. Сайт. Адрес, репозиторий сайта, регион, куда класть статьи. Приложение делает ключ доступа к репо, человек добавляет его в GitHub. Пробная выкладка черновика – проверка, что всё доезжает.
  7. Первый запуск. Станция «Знакомство»: завод собирает факты о компании, человек их подтверждает. Дальше завод идёт по станциям, а приложение показывает, где нужно «да».
Вход в Claude у клиента из России требует VPN только на минуту авторизации в браузере. Дальше Claude ходит с сервера NL, регион один.

Что берём готовым

Условия Anthropic и OpenAI

Anthropic, документация Agent SDK (дословно, 14.11.2026): «Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods… instead.»

Anthropic, авторизация Claude Code: долгий токен claude setup-token – «for CI pipelines, scripts», на год, только запросы к модели.

Условия подписки Anthropic (по отчёту исследователя, первоисточник прочитать юристу): нельзя давать свой аккаунт другим людям.

OpenAI: для автоматизации советует ключ API; вход через ChatGPT для доверенной автоматизации описан отдельным руководством – допускается. Пункт об автоматическом извлечении ответов – не проверен напрямую (сайт отдал 403).

Что это значит для продукта: «работает на обычной подписке» в продаваемой версии честно звучит так – на подписке Codex (ChatGPT), если юрист подтвердит условия OpenAI, Claude – ключом. В приложении и рекламе нельзя называть продукт «Claude Code»; допустимо «работает с Claude».

Обновление страниц: сигналы и правила

Обновляем не по календарю, а по сигналам сторожа (Google и Яндекс частоту не задают; агентства тоже сходятся на «по сигналам»). Плюс плановая сверка фактов: раз в 6 месяцев каждая страница проверяется на устаревшие цены, годы, модели; изменилась база фактов – затронутые страницы в очередь сразу. Подробно с источниками – разбор «Обходчик и обновление».

API пульт ⇄ движок (через туннель, версия v1)

  • GET /v1/version – версия движка и минимальная версия пульта; несовместимо – пульт предлагает обновить.
  • GET /v1/doctor – проверки установки, ключей, места, лимитов.
  • GET/POST /v1/sites, GET /v1/sites/{id}/stations
  • POST /v1/tasks – запустить станцию или задание словами; GET /v1/tasks?status=
  • GET /v1/approvals, POST /v1/approvals/{id} – «да» / «вернуть с комментарием»
  • GET /v1/pages, GET /v1/pages/{id} – черновик, гейты, история
  • PUT /v1/secrets/{name} – записать ключ; обратно отдаётся только маска и «работает / нет»
  • GET/PUT /v1/schedule – расписание; GET /v1/ledger – расходы и потолки
  • POST /v1/pages/{id}/rollback – откат выкладки
  • GET/POST /v1/users – люди и их подписки
  • POST /v1/license/activate, GET /v1/license – лицензия (движок сверяется с центром)
  • POST /v1/support-access – выдать временный доступ поддержке; DELETE – отозвать
  • GET /v1/track – «Мой путь»: шаги считает сам движок по своим данным и тем же правилам, что центр; центр получает их в сводке
  • POST /v1/update – обновить движок (см. «Обновление движка»)
  • WS /v1/stream – живой журнал событий
  • Совместимость: пульт версии N работает с движком N и N-1; старше – пульт просит обновить движок, младше – просит обновить себя.

Экраны приложения

  1. Командный центр. По каждому сайту: вышло за вчера и неделю, в очереди, ждёт моего «да», ошибки, расход месяца, лимит подписки.
  2. Сайт → станции. Лента 1–11 со статусами; в станции – результат, кнопки «запустить», «утвердить», «вернуть».
  3. Ждёт решения. Одна очередь: ядро, карта страниц, черновики.
  4. Страницы. Таблица: адрес, тип, статус, гейты, позиция, показы.
  5. Задание заводу. Поле «что сделать словами» – Claude работает в папке сайта по правилам завода, итог приходит черновиком на «да». Через это идут правки, ради которых раньше открывали чат.
  6. Журнал. Живой ход задач, стоимость каждой.
  7. Расписание. Что и когда запускается, вкл/выкл.
  8. Настройки. Сервер, нейросети и роли, ключи, сайт, уведомления, обновления; «Доктор».

Тёмная тема: вечером сама и по системе, переключатель запоминает выбор.

Безопасность

  • Песочница агентов. Claude и Codex читают чужие страницы (конкуренты из выдачи), а в странице может быть внедрённая команда. Поэтому: движок и агенты работают под разными непривилегированными пользователями; файлы секретов агенту не читаются; на станциях с веб-данными агенту разрешено только чтение – без запуска команд и без сети, кроме выдачи из кэша; «Задание заводу словами» работает в копии папки сайта, итог – только черновик; выкладку, git и платные запросы делает код движка после гейтов, а не агент.
  • Движок слушает только 127.0.0.1. Новых портов наружу нет; доступ – только SSH-туннель по ключу.
  • После установки вход на сервер только по ключу, fail2ban.
  • Токены и ключи – на сервере, права 600. В пульт и в журнал не попадают; в логах – маска.
  • На компьютере – только SSH-ключ, в связке ключей системы (Keychain / Диспетчер учётных данных).
  • Потолки денег держит движок: задача дороже потолка ждёт «да». Порог «без вопроса» задаётся в профиле сайта (у студии – XMLRiver до 150 ₽ на задачу).
  • Каждое внешнее действие (выкладка, переобход, платный запрос) – в журнале: кто, когда, чем.
  • Копия базы и данных сайта – каждый день, не на этом же сервере: в хранилище S3, которое указал владелец (для проектов РФ – Cloud.ru). «Доктор» раз в неделю пробно восстанавливает копию во временную папку.
  • Перед продажей – проверка скиллом «безопасность».

Обновление движка у клиентов

  1. Откуда. Центр выдаёт подписанный архив движка нужной версии. Движок проверяет подпись до распаковки.
  2. Кто запускает. Ты в панели выкатываешь версию волнами: 10 % флота → сутки без новых ошибок → все. Клиент видит «есть обновление» и может поставить сразу или ждать своей волны.
  3. Без остановки работы. Движок перестаёт брать новые задачи, ждёт конца текущих (не дольше 30 минут), делает копию базы, ставит новую версию рядом со старой, применяет миграции, переключается.
  4. Миграции базы. В базе хранится номер схемы; каждая миграция – отдельный шаг с тестом; перед миграцией копия.
  5. Откат. Новая версия не прошла «Доктора» за 10 минут – возврат на старую версию и старую копию базы, тревога в центр.
  6. Claude Code и Codex. Версии закреплены в движке, самообновление выключено (DISABLE_AUTOUPDATER у Claude Code); новые версии CLI приезжают только вместе с проверенной версией движка.
  7. Пульт обновляется отдельно через tauri-plugin-updater; правило совместимости N / N-1 – в разделе API.

Панель продавца: все клиенты, их путь и что требует тебя

Зачем. Продали 100 копий – нужно видеть всех в одном окне: кто где застрял, у кого завод встал, у кого уже результат, кому нужна твоя помощь, а кому нет. У Васина этого нет: результаты участников – скриншоты из закрытого чата, плюс 4 фазы уроков с отметками в кабинете (проверено на vasinki.ru/ceh 14.11.2026). Что уходит в центр, а что нет

Два уровня. «Я живой» и проверка лицензии – обязательны для всех: без них нет обновлений и поддержки. Суточная сводка – по согласию; без согласия клиент виден во «Флоте» серым: только жив / не жив, версия и шаг установки.

Защита отчёта. Каждый отчёт подписан ключом установки, который выдан при активации лицензии; в отчёте время и номер – повтор старого отчёта отбрасывается. Схема отчёта закреплена; поля не из схемы центр отбрасывает, движок перед отправкой фильтрует так же. Тест: в отправленном нет ни одного запрещённого поля.

«Идёт само» – зелёные: завод живой, шаги идут в срок. Их видно одной строкой, внимания не просят.

Экраны панели

  1. Флот. Все клиенты: светофор, шаг трека, дней на шаге, выложено за неделю, индекс, клики, версия. Фильтры и сортировка.
  2. Требует меня. Только красные и жёлтые, по важности; у каждого – причина и что сделать.
  3. Клиент. Трек с датами, история сводок графиком, ошибки, заметки, кнопка «запросить доступ» – клиенту приходит просьба, доступ на 2 часа открывает только он.
  4. Результаты. До / после по клиентам; разрешившие показ – готовые кейсы для продаж.
  5. Когорты. Купили в одном месяце – сколько дошли до каждого шага и за сколько дней. Видно, где продукт теряет людей и что чинить.
  6. Обновления. Версии по флоту, выкатка новой версии сначала на 10 %.

В приложении клиента – тот же трек на экране «Мой путь»: где он, что дальше, материал к шагу.

Критерии выхода этапов

Этап закрыт, когда выполнены все пункты и есть след: коммит, запись прогона, снимок экрана. «Почти готово» не считается.

Правила разработки для программистов

  • Новый закрытый репозиторий под код; git до первой строки кода. Коммит после каждого проверенного шага, описание по-русски.
  • Файл кода – до 800 строк; шаг – до 3 файлов кода вместе с тестами и настройками.
  • Каждый гейт и каждое правило конвейера – с тестом. Перед коммитом set -o pipefail.
  • В коде нет адресов наших серверов, путей мака, ключей, имён клиентов – только настройки.
  • Тексты интерфейса: короткое тире «–», без иероглифов; кнопка называет, что человек получит.
  • Правила студии (порог XMLRiver 150 ₽ без вопроса, часовой пояс МСК, «длинное тире – стоп», набор гейтов) – это профиль «Студия» в настройках сайта, а не код. У клиента свой профиль со своими значениями.
  • Перед выкладкой в main – скилл deploy-check; существенная правка – независимый change-reviewer.
  • Старый код студии (seozavod, avtostati, админка TEYES, РУКИ) не трогать; брать из него только логику как образец.
